# Root Configuration Guide

This file explains the important root-level configuration files in the project. Use it before changing build, lint, test, deployment, Sentry, env, or tooling behavior.

## Runtime And Package Management

- `package.json`: Defines the app metadata, npm scripts, dependencies, and dev dependencies. Check this before adding packages or changing commands such as `dev`, `build`, `lint`, `typecheck`, Vitest, and e2e scripts.
- `package-lock.json`: Locks exact dependency versions for reproducible installs. Regenerate it with `npm install` after dependency changes.
- `.nvmrc`: Documents the intended Node.js version family for local development and deployment alignment.
- `next-env.d.ts`: Generated by Next.js and ignored by git in this repo. Do not manually edit it.

## Main Package And Service Map

Use this section when someone asks what the project is built with and which external services it depends on.

- Core app runtime: `next`, `react`, `react-dom`, and TypeScript power the App Router frontend, server components, route handlers, layouts, loading states, and client components.
- Authentication: `next-auth` manages credentials login, Google OAuth login, sessions, and role-aware route/API checks. `@auth/mongodb-adapter` connects auth persistence to MongoDB.
- Database and models: `mongodb` and `mongoose` store users, restaurants, menu items, orders, coupons, reviews, notifications, messages, audit logs, and operational settings.
- Forms and validation: `react-hook-form`, `@hookform/resolvers`, and `zod` validate login, register, profile, restaurant, checkout, password, coupon, and admin forms.
- UI primitives: `radix-ui`, `@radix-ui/*`, local `components/ui`, `lucide-react`, `class-variance-authority`, `clsx`, and `tailwind-merge` support the dark UI system, dialogs, selects, tables, buttons, icons, and composable styling.
- Styling: Tailwind CSS 4 is wired through `tailwindcss`, `@tailwindcss/postcss`, `postcss.config.mjs`, and global CSS.
- Server state and tables: `@tanstack/react-query` handles cache/refetch/invalidation logic, while `@tanstack/react-table` powers professional admin tables.
- Media upload: `cloudinary` stores user avatars, restaurant images, category images, and menu-item images. Upload routes choose development/production folders and cleanup routes delete old Cloudinary public ids.
- Email: `resend`, `@react-email/components`, `@react-email/render`, and `react-email` send verification emails, password reset links, and purchase receipts from templates in `components/resend`.
- Payments: `stripe`, `@stripe/react-stripe-js`, and Stripe webhook routes create/recover Checkout sessions, verify completed payments, store `stripeSessionId`, and send receipt emails.
- Background jobs: `@upstash/qstash` schedules signed order-maintenance callbacks, unpaid-order cleanup, courier assignment timeout checks, and ready-without-courier checks.
- Rate limiting and cache: `@upstash/redis` and `@upstash/ratelimit` protect sensitive auth/profile/checkout/API actions from repeated abuse.
- Maps and delivery distance: `leaflet`, `react-leaflet`, and `leaflet-defaulticon-compatibility` support restaurant/customer/courier location UI and delivery map displays.
- Phone handling: `libphonenumber-js` normalizes international phone numbers so checkout/profile validation is not limited to one country.
- Money and dates: `currency.js`, `date-fns`, and `@date-fns/tz` keep totals, discounts, tax, delivery fees, reports, and timezone-aware display consistent.
- Reports and charts: `recharts` renders dashboard charts, and `@react-pdf/renderer` creates PDF report output.
- AI features: `openai` supports assisted menu item description generation.
- Observability: `@sentry/nextjs`, `@vercel/analytics`, and `@vercel/speed-insights` cover runtime errors, analytics, and performance monitoring.
- Testing: `vitest`, `jsdom`, `@testing-library/*`, `msw`, `mongodb-memory-server`, and `@faker-js/faker` support unit, integration, API, and e2e-style workflow tests.

## Next.js And React

- `next.config.ts`: Central Next.js configuration. Use this for image domains, Sentry plugin integration, experimental/framework settings, headers, redirects, or build-time behavior.
- `instrumentation.ts`: Server instrumentation entry point. This is where server-side observability setup can be registered.
- `instrumentation-client.ts`: Client instrumentation entry point. This is where browser-side monitoring setup can be registered.
- `sentry.server.config.ts`: Sentry server runtime configuration.
- `sentry.edge.config.ts`: Sentry edge runtime configuration.
- `sentry.client.config.ts` may not exist in this repo because client setup is currently handled through the newer instrumentation/client files.

## TypeScript

- `tsconfig.json`: TypeScript compiler settings, path aliases, strictness, JSX behavior, and included files. Use `npm run typecheck` after touching shared types, route handlers, or config.
- `tsconfig.tsbuildinfo`: TypeScript incremental build cache. It is generated and ignored by git.

## Linting And Formatting

- `eslint.config.mjs`: ESLint flat config. Use this to change lint rules, ignored paths, parser options, and framework-specific lint behavior.
- `.prettierrc`: Prettier formatting preferences.
- `.prettierignore`: Files and folders Prettier should skip.
- `.editorconfig`: Editor-level whitespace and newline defaults.

## Styling And UI Tooling

- `postcss.config.mjs`: PostCSS/Tailwind CSS pipeline entry. Tailwind CSS 4 integration is handled through this stack.
- `components.json`: shadcn/ui configuration, including aliases and component-generation behavior. Check this before adding or regenerating shadcn components.

## Testing

- `vitest.config.ts`: Main Vitest unit/integration test configuration. It sets aliases, setup files, and the test environment.
- `vitest.e2e.config.ts`: E2E-style Vitest configuration for route/workflow tests that need separate behavior.
- `TESTING.md`: Human-facing testing guide. Update it when adding new scripts, test groups, or test workflow expectations.

## Deployment

- `vercel.json`: Vercel deployment configuration. Use this for deployment-level overrides, cron/routing behavior, and Vercel-specific settings.
- `.dockerignore`: Files excluded from Docker build context if container workflows are used.
- `.gitignore`: Keeps dependencies, generated build output, env files, local scripts, and caches out of git.
- `.gitattributes`: Git file handling and line-ending behavior.

## Env And Secrets

- `example.env`: Safe template of required environment variables. Update this whenever app code starts requiring a new env variable.
- `.env.local`: Local secrets and machine-specific values. It is ignored by git and must never be committed.

Important env areas:

- MongoDB: `MONGODB_URL`, `MONGODB_URL_TESTS`
- Auth: `NEXTAUTH_URL`, `NEXTAUTH_SECRET`, Google OAuth keys
- Payments: `STRIPE_PK`, `STRIPE_SK`, `STRIPE_WEBHOOK_SECRET`
- Email: `RESEND_API_KEY`, sender/receiver emails
- Media: Cloudinary credentials
- Observability: Sentry DSN/auth token
- Background jobs: QStash URL/token/signing keys
- Cache/rate limit: Upstash Redis URL/token

## How External Services Fit Together

- Register and verification: `/api/register` creates the user, generates a token unless email verification is skipped locally, renders a React Email template, and sends it through Resend.
- Forgot password: `/api/forgot-password` rate-limits the email address, stores a hashed reset token in MongoDB, and sends the raw token inside a Resend password-reset URL.
- Reset password: `/api/reset-password` hashes the submitted token, finds an unexpired matching user, validates the new password, hashes it with bcrypt, and clears the token fields.
- Profile and image upload: profile screens call `/api/upload/users`, which streams files to Cloudinary, stores the returned secure URL on the user, and deletes the old Cloudinary image when possible.
- Restaurant/menu media: admin restaurant and menu item forms upload to Cloudinary through dedicated upload routes, then save final URLs through restaurant/menu APIs.
- Checkout: `/api/checkout` validates cart, restaurant status, delivery radius, courier readiness, coupons, loyalty, quantity/capacity limits, and then creates or reuses a Stripe Checkout session.
- Payment completion: `/api/webhook` verifies Stripe signatures, marks orders paid, sends receipt emails through Resend, and triggers notification/order side effects.
- Order maintenance: QStash calls signed maintenance routes later so stale unpaid orders, courier assignment timeouts, and ready orders without courier coverage can be handled even after the original request finished.
- Monitoring: Sentry catches app/runtime errors, while Vercel Analytics and Speed Insights give production usage/performance signals.

## Observability

- Sentry config files plus `instrumentation*.ts` control error/performance monitoring.
- Vercel Analytics and Speed Insights are mounted inside app layout code, not from root config only.
- Keep replay sampling conservative, especially outside production.
